# UHERO Data MCP Tool

The MCP server (`uhero-data`) lets Claude clients (claude.ai connectors, Claude Code, etc.) query UHERO time-series data through the UDAMAN app. It is a thin, authenticated wrapper around the public UHERO API (`https://api.uhero.hawaii.edu/v1`). UHERO staff can also reach the restricted API (`/v1.u`).

## Key files

| File | Role |
| --- | --- |
| `src/app/api/mcp/route.ts` | HTTP endpoint (`/api/mcp`): auth, per-request server setup, transport |
| `src/lib/mcp-tools.ts` | Registers the tools and holds all per-tool logic |
| `src/lib/uhero-client.ts` | Fetch wrapper for the UHERO REST API (uses `REST_API_TOKEN`) |
| `src/lib/series-code.ts` | Parses/formats codes like `UR@HON.M`, clamps date ranges |
| `src/lib/auth/roles.ts` | `canAccessRestrictedData(role)`: true for `admin`, `dev`, `internal` |
| `src/app/.well-known/oauth-protected-resource/api/mcp/route.ts` | RFC 9728: names our server as the authorization server for `/api/mcp` |
| `src/app/.well-known/oauth-authorization-server/route.ts` | RFC 8414: lists the authorize, token, and register endpoints (PKCE S256) |
| `src/app/api/oauth/{authorize,token,register}/route.ts`, `src/app/oauth/consent/page.tsx` | The OAuth flow itself |

## Request flow

```
Client ──POST/GET/DELETE/OPTIONS /api/mcp──▶ handle(req)
                                              │
                                              ▼
                                        resolveAuth(req)
                   ┌──────────────────────────┴──────────────────────────┐
     Authorization: Bearer <token>?                                No bearer header
                   │                                                     │
   OAuthController.validateBearer(token)                        NextAuth auth() cookie session
       valid ──▶ ctx + role read live from `users`              session.user.id? ──▶ ctx (role from session)
       invalid ──▶ null (no cookie fallback)                     none ──▶ null
                   └──────────────────────────┬──────────────────────────┘
                                              ▼
                              ctx == null ──▶ 401 + JSON-RPC error
                                              WWW-Authenticate: Bearer resource_metadata=
                                              <origin>/.well-known/oauth-protected-resource/api/mcp
                                              │
                                              ▼ (authorized)
                    new McpServer("uhero-data") per request
                    registerUheroTools(server, { userId, userEmail, role })
                    new WebStandardStreamableHTTPServerTransport
                      (stateless: no session id; JSON responses, not SSE)
                    server.connect(transport)
                    return transport.handleRequest(req)
                    finally: close transport + server
```

Notes:
- **Stateless.** Every request builds a fresh server and transport, so nothing is kept between calls and horizontal scaling is not a concern.
- **Live role lookup.** For bearer tokens the role comes from `SELECT role FROM users` on every request, not from the token. A demotion takes effect on the next call, not when the 30-day token expires. A deleted user falls back to `external`.
- **OAuth discovery.** A 401 response points to the protected-resource metadata. From there Claude finds the authorization-server metadata, registers itself dynamically, and runs authorization-code + PKCE. After that it retries with a bearer token.

## Tools

Every response is JSON text with a `source` object (UHERO citation) attached. Every call is logged as a `mcp_tool_call` JSON line containing the user id, email, role, and input.

| Tool | What it does |
| --- | --- |
| `search_series` | If the input is a code (`NAME@GEO.FREQ`), does an exact lookup. Otherwise runs a free-text search, and if a multi-word query finds nothing it retries with the first word. Returns up to 10 matches plus a `disambiguation_hint`. It sets `next_step: "ask_user_to_pick"` when a free-text search is ambiguous. |
| `list_series_in_group` | Fuzzy-matches a topic name to a UHERO category (or takes a `category_id`) and returns up to 30 series. |
| `get_observations` | Returns one series by id or code. Supports an optional `YYYY[-MM]` range (default: the full published range) and a transform (`lvl`, `pch`, `pc1`, `ytd`, `chg`, `ch1`). |
| `compare_series` | Takes 2–8 ids or codes, resolves them in parallel, and aligns them on the union of their dates as a wide table (`dates[]` + `series[].values[]`). Warns about mixed frequencies and about entries that failed or are restricted. |
| `list_geographies` | Returns the built-in list of Hawaii handles, or, when `sample_series_id` is given, the live list of geographies for that series. |
| `list_frequencies` | Static list: A/Q/M/W/D. |
| `list_series_siblings` | Returns the same measure in other geographies and frequencies. Its output feeds straight into `compare_series`. |

Every series in a result goes through `projectSeries()`. That gives it a readable code, a name, geography, units, date span, and a per-series `citation` string. The tool descriptions tell Claude to use that citation word for word.

## Restricted-data logic

- `get_observations` and `compare_series` accept `unrestricted: true`. In that mode:
  - The caller's role must pass `canAccessRestrictedData`; otherwise the tool returns `RESTRICTED_ACCESS_DENIED`.
  - Inputs must be codes (`/v1.u` has no id lookup), and only the `lvl` transform works (observations come inline from `expand=true`).
  - The response is marked `access: "restricted"` and includes an `access_note`. The tool description tells Claude to tell the user this, including in later answers.
- On a normal public lookup of a code that fails, `classifyMissingCode()` checks `/v1.u` to tell **not found** apart from **exists but restricted**. The public API returns the same empty `{id:0, name:""}` in both cases. The error message then depends on the role:
  - Staff are told to retry with `unrestricted: true`.
  - Everyone else is told to report that the series is restricted and not to retry.

## Error handling

Each tool body is wrapped in try/catch and returns `{ error: safeError(err) }`, never throwing. Errors from the UHERO API are reduced to their status code, and any `Bearer …` string is redacted from error messages.
